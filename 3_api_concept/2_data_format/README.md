## Response Section
**เปรียบเทียบความแตกต่างของ JSON กับ Protocol Buffer**
| JSON 	    | Protocol Buffer 	|
| :---    | :---         |
| เก็บข้อมูลในรูปแบบ `Text-based` แบบ key: value | เก็บข้อมูลในรูปแบบ `Binary` ออกแบบมาเพื่อให้โปรแกรมประมวลผล |
| ความเร็วในการแปลข้อมูลช้า เพราะต้อง parse ข้อความ | ความเร็วในการแปลข้อมูลเร็ว อ่าน-เขียน ในระดับไบต์ |
| มนุษย์อ่านเข้าใจได้ง่าย | มีไฟล์ `.proto` ช่วยถอดรหัสเพื่อแปลชุดไบต์เป็นข้อความที่คนอ่านเข้าใจได้ |
| `Schema` ยืดหยุ่น | `Schema` เข้มงวดต้องกำหนดชนิดข้อมูลในไฟล์ `.proto` ไว้ล่วงหน้า |

**ข้อดี และข้อเสีย ของแต่ละรูปแบบ**

***JSON***

|      | ข้อดี | ข้อเสีย |
| :--- | :--- | :--- |
| **JSON** | อ่านและ Debug ง่าย | ขนาดข้อมูลใหญ่: ต้องส่งชื่อ key ซ้ำทุกครั้งทำให้เปลือง `Bandwidth` เมื่อรับส่งข้อมูลปริมาณมาก |
| | เริ่มใช้งานได้เร็ว: ไม่ต้องเขียน schema หรือคอมไพล์ก่อนใช้งาน | แปลงข้อมูลช้าและกิน CPU มากกว่า `Protobuf` |
| | โครงสร้างยืดหยุ่น: เพิ่มหรือลดฟิลด์ได้อิสระ | ไม่บังคับชนิดข้อมูลในตัว: เกิดความเสี่ยงข้อมูลผิดประเภทหรือพิมพ์ผิด |
| | เครื่องมือรองรับเยอะ และใช้งานบน Browser ได้โดยตรง | ชนิดข้อมูลจำกัด: ต้องแปลงเป็น `Base64` |

***Protocol Buffer***

|      | ข้อดี | ข้อเสีย |
| :--- | :--- | :--- |
| **Protocol Buffer** | ขนาดเล็กมาก: ข้อมูลเป็น `Binary` และใช้หมายเลขฟิลด์แทนชื่อฟิลด์ | ต้องมีไฟล์ `.proto` และเครื่องมือช่วยถอดรหัส ในการเข้าอ่าน|
| | เร็วและประหยัด CPU | ต้องจัดการไฟล์และรันคอมไพล์ใหม่ทุกครั้งที่มีการปรับโครงสร้างข้อมูล |
| | มีโครงสร้างข้อมูลที่ชัดเจน | ไม่เหมาะกับโครงสร้างที่ไม่แน่นอน |
| | รองรับการอัปเดตเวอร์ชันได้ดี | ใช้งานบน web browser ไม่สะดวกเท่า JSON |
