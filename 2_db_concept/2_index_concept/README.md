## Response Section
- **ข้อดี**
    - ค้นหาและอ่านข้อมูลได้เร็วขึ้นมาก
        - เปลี่ยนจากค้นหาทั้งตาราง เป็นค้นหาแบบ tree 
    - column ที่มีการเชื่อมตาราง ถ้ามี index จะทำให้การจับคู่ตารางได้ไวขึ้น
    - ลดภาระการประมวลผลและการเรียงลำดับของข้อมูล
        - โครงสร้างของ index จะมีการจัดเก็บแบบ pre-sorted บนฐานข้อมูล ทำให้เมื่อมีการ query ด้วย WHERE, ORDER BY และ LIMIT ทำให้ได้ผลลัพธ์ตามลำดับที่เรียงไว้แล้ว ไม่ต้องมา sort ข้อมูลใหม่

- **ข้อกำจัด**
    - เขียนข้อมูลลงฐานข้อมูลช้าลง
        - เมื่อฐานข้อมูลมีการอัปเดต ต้องอัปเดต index ทุกตัวที่เกี่ยวข้อง ทำให้ยิ่งมี index มาก ยิ่งใช้เวลาในการเขียนมากขึ้น
    - กินทรัพยากร ram หรือ cache มาก 
        - index จะเก็บไว้ใน buffer cache หรือ ram เพื่อความเร็วในการอ่านข้อมูล ซึ่งจะทำให้เมื่อ index มีขนาดใหญ่ขึ้นจะทำให้ทรัพยากรในการจัดเก็บ index ใหญ่ขึ้นมาก
    - ต้องออกแบบและดูแลรักษา
        - index ที่ไม่ได้ใช้จะเป็น idle 
        - index ต้องมีการ rebuild เป็นระยะๆ เพื่อป้องการ fragmentation
